# Бизнес-экран прогноза

Веб-интерфейс встроен в существующий `forecast_api_server.py`.
Новый frontend-сервер, Node.js, сборка и дополнительные Python-библиотеки не нужны.

## Запуск

Перенесите обновлённые `forecast_api_server.py` и `forecast_ui.html`
в одну папку либо обновите репозиторий. Остановите предыдущий сервер через Ctrl+C.
Из папки проекта, в вашем активированном окружении:

```bash
python experiments/forecast_api_server.py --model-dir "/путь/к/saved_model"
```

В `saved_model` нужны `forecasts_api.parquet` и `model_metadata.json`.
Откройте **http://127.0.0.1:8000/** в браузере на том же ПК.
Swagger по адресу `/docs` и прежние методы `/forecast` продолжают работать.

Если задан `--api-key`, раскройте «Ключ доступа к API» слева, введите его
и нажмите «Подключиться». Ключ не сохраняется в localStorage и не отправляется
сторонним сервисам. Без ключа API не защищает клиентские данные: не открывайте
сервер в интернет. Для удалённой ВМ предпочтителен SSH-туннель.

## Что показать бизнесу за минуту

1. Слева выберите **ИНН из файла**. Можно искать по первым цифрам;
   список ограничен 15 совпадениями, чтобы не загружать в браузер всех клиентов.
2. Выберите **месяц из списка** — только периоды этого ИНН из Parquet.
   Отдельных дней в месячном файле нет.
3. Покажите три карточки: поступления, списания, чистый денежный поток.
4. Прочитайте пояснение под карточками. Оно меняется вместе с клиентом и месяцем.
5. При желании введите доступный остаток **на начало выбранного месяца**.
   Расчётный остаток на конец = начальный остаток + поступления − списания.
   Это сценарий с введённым вами остатком, не дополнительный выход модели.
6. Нажмите «Скопировать вывод» для текста в письмо/презентацию или «Печать / PDF».

Остаток автоматически очищается при смене клиента или месяца: вчерашний остаток
нельзя без проверки переносить на начало другого прогнозного периода.

## Как объяснять результат корректно

> Это прогноз суммарных поступлений и списаний по клиенту за месяц. Разница
> показывает ожидаемый приток или отток денег. Она не является прибылью и не
> равна остатку на счёте. Для оценки остатка нужен начальный баланс; для даты
> кассового разрыва нужен дневной прогноз. Сейчас показан заранее рассчитанный
> результат из файла, а не пересчёт модели на новых операциях.

В интерфейсе указано, по какой месяц доступна исходная история (если поле
`last_complete_month` сохранено в метаданных). Отсутствующая дата не заменяется
сегодняшней. Качество, доверительные интервалы и вероятности не выдумываются:
если их нет в файле, экран прямо говорит об этом.

График показывает месячные суммы поступлений и списаний, а не остатки.
Положительный итог месяца не исключает дефицит внутри месяца. Последующие
рекурсивные прогнозы используют предыдущие прогнозы как часть истории.

## Проверка

```bash
python -m unittest discover -s experiments -p test_forecast_api_server.py -v
```

Для тестов дополнительно нужен `httpx`. Они создают только искусственные записи
во временной папке; реальные файлы клиента не изменяются.
