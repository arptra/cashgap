# Все ИНН с отрицательным фактическим денежным потоком

`export_negative_cashflow.py` принимает два Parquet-файла и находит **все дни
2025 года, когда у ИНН сумма поступлений за день меньше суммы списаний**.
Каждая строка результата — конкретный ИНН и календарная дата. Сначала суммируются
все операции обеих сторон за день, затем проверяется знак разности.

Это расчёт фактов, модель и обучение не нужны. Отрицательный дневной поток
не равен отрицательному итогу месяца или года. Он также не подтверждает кассовый
разрыв: для этого нужны остатки, доступные кредитные лимиты и обязательные платежи.

## Запуск

Нужны Python 3.8+ и PyArrow. Скрипт работает отдельно от приложения: можно
скопировать только этот `.py` на сервер. Не нужны Torch, GPU, Node.js и API.

```bash
python -m pip install pyarrow

python experiments/export_negative_cashflow.py \
  --outflow "/data/outflow.parquet" \
  --inflow "/data/inflow.parquet"
```

По умолчанию год — **2025**, каталог результата —
`artifacts/negative_cashflow_2025`. Для другого года/каталога:

```bash
python experiments/export_negative_cashflow.py \
  --outflow "/data/outflow.parquet" \
  --inflow "/data/inflow.parquet" \
  --year 2025 \
  --output-dir "/data/reports/negative_cashflow_2025"
```

В Jupyter после установки PyArrow:

```python
%run experiments/export_negative_cashflow.py --outflow "/data/outflow.parquet" --inflow "/data/inflow.parquet"
```

Этот скрипт выполняется до завершения в текущем процессе. Периодически выводится
число прочитанных операций. Для повторной записи в тот же каталог добавьте
`--overwrite`; по умолчанию имеющиеся результаты сохраняются.

## Входные данные

| Файл | Поля | Смысл |
|---|---|---|
| `outflow.parquet` | `tr_date`, `dt_inn`, `tr_sum` | Списания |
| `inflow.parquet` | `tr_date`, `kt_inn`, `tr_sum` | Поступления |

Поддерживаются варианты `dtinn`/`ktinn` и различия регистра/подчёркиваний.
Вместо файла можно передать каталог с частями одного Parquet dataset.

- `tr_sum` — **положительная сумма в рублях** на обеих сторонах. Скрипт сам
  вычитает расходы. Отрицательные, пустые и некорректные суммы за выбранный год
  вызывают ошибку; нельзя автоматически брать модуль возвратов/сторно.
- Все суммы должны быть в одной валюте. Конвертации валют и фильтра по валюте нет.
- ИНН хранится как строка из 10 или 12 цифр, начальные нули сохраняются.
  Поддерживаются целочисленные значения и целые float, например `7700000001.0`.
  Уже потерянные при выгрузке начальные нули восстановить нельзя. Контрольная
  сумма ИНН не проверяется.
- Дата: Parquet date/timestamp, число или строка `20250530`, ISO-дата/время,
  строка `30.05.2025`, числовой Unix timestamp (s/ms/us/ns) или дни от 1970-01-01.
  У timestamp используется записанная календарная дата без смены часового пояса;
  числовой Unix timestamp трактуется в UTC. Обе стороны должны использовать один
  календарь. Час и момент перехода внутри дня не определяются.

Включаются даты с 1 января по 31 декабря выбранного года, обе границы включены.
Первый и последний месяцы не отбрасываются. История прошлых лет не требуется.
Все строки с некорректной датой останавливают запуск; суммы и ИНН проверяются
только у операций выбранного года. Повторяющиеся строки считаются отдельными
операциями: без идентификатора транзакции надёжно удалить дубли невозможно.

## Результаты

| Файл | Содержимое |
|---|---|
| `negative_days_2025.csv` | Все пары ИНН/дата с отрицательным дневным потоком; поступления, списания, разность и положительная сумма превышения списаний |
| `inn_summary_2025.csv` | По одному ИНН: число отрицательных дней, первая/последняя дата, **полные годовые обороты** и годовой поток, сумма и максимум дневных превышений |
| `negative_months_2025.csv` | Отрицательные месячные итоги по ИНН, рассчитанные по **всем** операциям месяца |
| `run_summary_2025.json` | Число клиентов/событий, параметры, найденные колонки, даты операций и счётчики обработки каждого источника |

CSV: UTF-8 с BOM, разделитель `;`, десятичная запятая, суммы в рублях.
Для сохранения начальных нулей импортируйте ИНН в Excel как **текст**.
Строки упорядочены по ИНН и дате/месяцу. При отсутствии отрицательных потоков
создаются CSV с заголовками и нулевыми счётчиками. Если в обоих источниках вообще
нет операций за выбранный год, запуск завершается ошибкой.

Пример: 10 января пришло 100 ₽, ушло 150 ₽; 11 января пришло 200 ₽, ушло 0 ₽.
В дневной выгрузке будет **10 января, −50 ₽**. Итог этих двух дней **+150 ₽**;
нельзя записывать его как отрицательный месячный поток.

Сумма дневных превышений — характеристика потоков, **не кредитный лимит, не
сумма подтверждённых кассовых разрывов и не финансовая выгода**. Годовые итоги
в сводке включают также положительные дни. Если нужны ИНН с отрицательным итогом
всего года, отберите в сводке `Чистый поток за год, руб. < 0`.

## Обработка больших файлов и контроль

Читаются только три нужные колонки порциями по 131 072 строк. Промежуточные
агрегаты ИНН/дата сохраняются во временную SQLite в каталоге результата; все
транзакции не загружаются в RAM. На этом диске нужно место для дневной витрины
и отчётов. При необходимости уменьшите порцию: `--batch-size 32768`.

Расчёт ведётся в целых копейках, без ошибок сложения float. Каждая исходная сумма
округляется до копейки по `ROUND_HALF_UP`; число округлённых значений записывается
в JSON. Переполнение целочисленных сумм приводит к ошибке.

Результаты публикуются после успешного чтения обеих сторон и создания всех
отчётов. Ошибочные операции не заменяются нулями. Отсутствие записи по стороне
ИНН/даты трактуется как нулевой поток. Полноту исходных выгрузок программа
установить не может: проверьте, что предоставлены обе стороны за весь год.

Проверка на искусственных данных:

```bash
python -m unittest discover -s experiments -p test_export_negative_cashflow.py -v
```
