# Полный фронт «ИИ адъютант про» + API прогноза

Сохранён весь предоставленный TypeScript-фронт: шапка, меню, карточки,
рекомендации, контрагенты, сравнения, движение средств и панель чата.
Исходная папка `pro.assit 2/frontend` не изменялась: здесь переносимая копия
дизайна, подключённая к Python-серверу проекта cashgap.

## Запуск на ВМ / другом ПК

Из корня проекта в активированном Python-окружении:

```bash
python experiments/forecast_api_server.py \
  --model-dir "/путь/к/saved_model" \
  --ui adjutant \
  --daily-allocation
```

Открыть **http://127.0.0.1:8000/**. Java, Spring Boot, Node.js и npm на ВМ
для запуска не нужны: скомпилированные JS-файлы уже лежат в `public/`.
Зависимости Python те же: `fastapi`, `uvicorn`, `pandas`, `pyarrow`;
сервер проверяет их при запуске и выводит команду установки при отсутствии.

В `saved_model` нужны `model_metadata.json` и `forecasts_api.parquet`.
Этот экран читает сохранённые прогнозы, не запускает `.pt` на новых операциях.

Если переносите вручную, копируйте `forecast_api_server.py`,
`adjutant_dashboard.py` и всю папку `liquidity_ui` с сохранением расположения.
Для старого интерфейса также нужен `forecast_ui.html` рядом с сервером.

Без `--daily-allocation` этот фронт показывает месячные суммы.
Без `--ui adjutant` открывается прежний бизнес-экран.
Для доступа по сети настройте безопасное соединение и `--api-key`;
предпочтителен SSH-туннель. Не открывайте клиентские данные в интернет без защиты.
В интерфейсе ключ вводится в «Ключ доступа к API», хранится только в памяти
вкладки и передаётся заголовком `X-API-Key`, не в URL.

## Что подключено

**Только «Анализ ликвидности» использует выбранный ИНН и прогноз.**
Остальные карточки сохранены из макета и подписаны как демонстрационные.
Баланс 118 млн в шапке, рекомендации кредита, коэффициенты, контрагенты,
отраслевые сравнения и ответы чата — не данные выбранного клиента.
Никакие кредиты, платежи или реальные обращения из демо не отправляются.

В виджете:

1. Введите начало ИНН и выберите реальный номер из совпадений Parquet.
2. Выберите месяц и, при включённом распределении, начальную дату.
3. Посмотрите поступления, списания и чистый поток за выбранное окно.
4. При необходимости введите свой остаток **на начало выбранного дня**
   (в месячном режиме — на начало месяца) и нажмите «Рассчитать остаток».
5. Под графиком раскройте дневную таблицу.

График показывает поступления и списания столбцами; линия — чистый поток,
а после ввода начального остатка — расчётный остаток. Отрицательные значения
показаны ниже нуля. Шкала автоматически выбирает рубли, тысячи или миллионы.
Начальный остаток сбрасывается при смене ИНН, месяца или начальной даты.
При ошибке старые числа скрываются, а не выдаются за новый результат.

Это **не коэффициент ликвидности** и не вероятность кассового разрыва.
Для коэффициента нужны отдельные данные об активах и обязательствах.
Дневные суммы получаются равномерным распределением месячного прогноза
по календарным дням, включая выходные. Месяц делится на 28–31 день, не на 14.
На переходе месяца берётся его собственный прогноз; при отсутствии
следующего месяца неподдерживаемые даты не предлагаются.
Реальные сроки платежей неизвестны: условная дата отрицательного остатка
не является предсказанной датой кассового разрыва.

## API для полного фронта

```text
GET /api/dashboard
GET /api/dashboard?inn=7700000001&period=2026-01&start_date=2026-01-25
GET /api/dashboard?inn=7700000001&period=2026-01&start_date=2026-01-25&opening_balance=1000000.50
```

ИНН и даты выше — примеры: подставьте значения из своего файла.
Без параметров берётся первый ИНН и первый доступный месяц.
`start_date` должен принадлежать выбранному месяцу, окно включает эту дату
и следующие 13 дней. `opening_balance` необязателен, в рублях, до 1 трлн по модулю.
Не передавайте в него демонстрационный баланс из шапки.

Ответ сохраняет разделы исходного фронта:
`company`, `metrics`, `recommendation`, `counterparties`, `comparisons`,
`cashFlow`, `assistant`. В `liquidityAnalysis` возвращаются:

- `series` / `categories` — денежные ряды для графика, **в рублях**, не условные коэффициенты;
- `rows` — дневные строки либо одна месячная строка;
- `totals` — суммы поступлений, списаний и чистого потока;
- `context` — выбранный ИНН, периоды, даты, источник, модель, введённый
  остаток и ограничения расчёта.

Поиск клиентов: `GET /ui/clients?q=770` (до 15 совпадений).
Прежние `/forecast`, `/ui/timeline`, `/health` остаются без изменения.
Все методы с данными защищены общим ключом, если он настроен.

## Изменение TypeScript

Нужно только разработчику, не для запуска на ВМ:

```bash
cd experiments/liquidity_ui
npm ci
npm run typecheck
npm run build
```

После сборки переносите также обновлённые `public/main.js` и
`public/forecast-widget.js`. `public/styles.css` — исходный стиль макета;
`public/forecast-widget.css` — стили подключённого виджета и отметок демо.
`demo_dashboard.json` содержит исходные демонстрационные данные остальных блоков.

Проверка API из корня проекта:

```bash
python -m unittest discover -s experiments -p test_forecast_api_server.py -v
```
