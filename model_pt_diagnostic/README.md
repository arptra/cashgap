# Отдельный сервер диагностики model.pt

Перенесите на другой ПК **только `server.py`**. Репозиторий, обучающие данные,
PyTorch, CUDA, pandas, FastAPI и установка библиотек не нужны.
Поддерживается Python **3.8 и новее**. В начале запуска выводится проверка версии.

Это инструмент, чтобы выяснить, что находится в неизвестном файле модели.
**Он не делает прогноз по ИНН и не обучает модель.** Сначала получите отчёт,
передайте его для разбора — затем можно определить, как запускать именно вашу модель.

## Запуск на Windows

Сохраните `server.py` в отдельную папку. Откройте в ней PowerShell или CMD:

```powershell
py -3 server.py
```

Если команда `py` отсутствует, но Python установлен:

```powershell
python server.py
```

## Запуск на Linux или macOS

```bash
python3 server.py
```

Сервер напечатает полный адрес вида:

```text
http://127.0.0.1:8765/#token=СЛУЧАЙНЫЙ_ТОКЕН
```

1. Скопируйте **весь адрес из своей консоли**, включая `#token=...`, в браузер
   на том же ПК. Не используйте буквальный пример выше.
2. Выберите свой `model.pt` и нажмите «Проверить файл».
3. Скачайте **model_report.md** и **model_report.json**.
4. Просмотрите отчёты перед передачей: в них есть названия признаков, классов
   и метаданные, которые могут быть внутренней информацией.
5. Передайте оба отчёта в чат. Саму модель передавать не обязательно.

Отчёты также сохраняются в `reports` относительно папки запуска, с уникальными
именами. В консоли печатается полный путь. Файл модели хранится временно только
на время запроса, затем удаляется. Никаких внешних отправок нет.

Остановка: **Ctrl+C**. Если порт занят:

```bash
python server.py --port 8766
```

## Если запускать из Jupyter

Не используйте `%run`, чтобы не занимать ядро сервером. В папке с `server.py`:

```python
import subprocess
import sys

server_log = open("model_diagnostic_server.log", "a", encoding="utf-8")
diagnostic_process = subprocess.Popen(
    [sys.executable, "-u", "server.py"],
    stdout=server_log,
    stderr=subprocess.STDOUT,
)
print("PID:", diagnostic_process.pid)
```

В следующей ячейке посмотрите адрес:

```python
from pathlib import Path
print(Path("model_diagnostic_server.log").read_text(encoding="utf-8")[-5000:])
```

Если браузер и Python находятся на разных машинах, `127.0.0.1` в браузере
указывает на машину браузера, а не на удалённую ВМ. Используйте SSH-туннель
на ПК с браузером (замените USER и SERVER реальными значениями):

```bash
ssh -N -L 8765:127.0.0.1:8765 USER@SERVER
```

После этого откройте локальный адрес с токеном, напечатанным удалённым сервером.
Остановить запущенный из ноутбука процесс можно отдельной ячейкой:

```python
diagnostic_process.terminate()
diagnostic_process.wait(timeout=10)
server_log.close()
```

## Что входит в диагностику

- Формат контейнера: обычный ZIP `torch.save`, старый `torch.save`, возможный
  TorchScript или неизвестный pickle-контейнер.
- Размер файла и SHA-256 для идентификации.
- Верхнеуровневые поля, найденные названия признаков, слои, активация и настройки.
- Имена и формы поддерживаемых тензоров, число элементов, тип хранения и
  устройство, указанное при сохранении. CUDA при этом не нужна и не запускается.
- Предполагаемая цепочка полносвязных слоёв, если размеры совместимы.
- Несоответствия между найденными признаками, объявленными слоями и размерами.
- Ссылки на классы и функции внутри файла — без их импорта и выполнения.
- Пояснение, какие данные и код ещё потребуются для настоящего прогноза.

Для знакомого месячного формата Cashgap v2 отдельно объясняется контракт
поправки к среднему. Для неизвестной модели число выходов **не трактуется**
автоматически как «дни», «вероятности», «зачисления» или «списания».

## Ограничения

Сервер не использует `torch.load`, `pickle.load`, `torch.jit.load`, `eval` или
импорт пользовательских классов. Он читает pickle-операции как инертное описание.
По одному state_dict невозможно достоверно восстановить forward, активации,
бизнес-смысл признаков, качество модели и все преобразования данных.

Поддерживаются распространённые плотные тензоры PyTorch. Для экзотических,
квантованных/разреженных тензоров, больших pickle-метаданных, внешних буферов,
очень старых TAR-контейнеров и нестандартных классов отчёт может быть неполным.
Частичный отчёт тоже полезен — передайте его, не включайте небезопасную загрузку.
Числовые значения весов не проверяются; успешный разбор структуры не означает,
что модель целая, правильно обучена или сможет выполнить предсказание.

Разбор выполняется в отдельном процессе, по одному файлу за раз, с тайм-аутом
45 секунд. Это снижает влияние ошибок разбора, **но не является ОС-песочницей**.
Не проверяйте файлы заведомо враждебного происхождения на машине с секретами.
Максимальный файл по умолчанию 256 МБ, pickle-описание ограничено 16 МБ.

Сервер по умолчанию доступен только на этом ПК, запросы защищены случайным
токеном. Это временный диагностический инструмент, не production-сервис.
Не публикуйте его в интернете. Доступ по LAN через `--host 0.0.0.0` возможен
только в доверенной сети: HTTP не шифрует ни модель, ни токен.

## Самопроверка (необязательно)

Если перенесён также `test_server.py`:

```bash
python -m unittest -v test_server.py
```

Тесты создают только искусственные файлы. Имеющиеся модели и данные не ищутся.

## Основания для статического подхода

- [Python: pickletools читает описание, не исполняя pickle-байткод](https://docs.python.org/3/library/pickletools.html).
- [PyTorch: структура torch.save и ограничения state_dict](https://docs.pytorch.org/docs/2.6/notes/serialization.html).
- [Уязвимость weights_only в PyTorch до 2.6](https://github.com/pytorch/pytorch/security/advisories/GHSA-53q9-r3pm-6pq6).

Здесь не требуется устанавливать старый Torch ради инспекции старой модели.
